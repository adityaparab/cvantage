# Email Monitor — Full-stack monorepo

A single repository containing:

- **`/` (root)** — a [NestJS](https://nestjs.com) API server (`src/`).
- **`/client`** — a [React](https://react.dev) + [Vite](https://vite.dev) single-page app.

In **production** the NestJS server serves the compiled React app: hitting the
server's base URL returns the SPA, `/api/*` hits the backend, and any unknown
path (a client-side route deep link like `/about`) falls back to `index.html`
so React Router can render it.

## How it fits together

| Concern | Mechanism |
| --- | --- |
| Serve the built SPA | `ServeStaticModule` in [`src/app.module.ts`](src/app.module.ts) points at `client/dist`. |
| Keep API + SPA separate | Global `api` prefix in [`src/main.ts`](src/main.ts); every backend route is under `/api`. |
| SPA deep-link 404 fallback | `ServeStaticModule` serves `index.html` for any non-`/api` path that isn't a real file. |
| API 404s stay JSON | `exclude: ['/api/{*path}']` keeps unknown `/api/*` routes on the Nest router (JSON 404), not the SPA. |
| Dev without CORS | Vite dev server proxies `/api` → `http://localhost:3000` (see [`client/vite.config.ts`](client/vite.config.ts)). |

## Install

```bash
yarn install:all   # installs root + client dependencies
```

## Develop (two servers, hot reload)

```bash
yarn dev
```

- API on http://localhost:3000 (`nest start --watch`)
- Client on http://localhost:5173 (Vite HMR) — **open this URL while developing**.
  Its `/api` calls are proxied to the API, so the code is identical to production.

## Production (one server serves everything)

```bash
yarn build         # builds client -> client/dist, then server -> dist
yarn start:prod    # node dist/main — serves the SPA + API on port 3000
```

Then open http://localhost:3000. `PORT` overrides the port.

## Project setup

```bash
$ yarn install
```

## Compile and run the project

```bash
# development
$ yarn run start

# watch mode
$ yarn run start:dev

# production mode
$ yarn run start:prod
```

```bash

$ yarn run test

# e2e tests
$ yarn run test:e2e

# test coverage
$ yarn run test:cov
```

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash

```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
